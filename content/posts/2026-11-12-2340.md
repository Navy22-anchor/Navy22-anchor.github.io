## Jev란?
Jev는 TypeSafe에서 2026.09.15일에 출시한 System One Model의 한 종류이다. System One Model이란 TypeSafe에서 정의한 프론티어 모델의 새로운 종류이다. System One Model은 빠르고 구조화된 결정과 판단을 하고, 그 결정을 소프트웨어에서 곧바로 쓸 수 있는 모델로 정의되며 System Two Model 또한 정의했다. System Two Model는 긴 추론 단계들로 수학과 복잡한 추론에서 탁월하지만 취약하며 비싼 모델로 정의와 동시에 비판을 하며 System One Model의 필요성을 강조했다.


### Jev의 입력과 출력형태는 무엇일까?

우리가 일반적으로 사용하는 GPT, Gemini, Claude 들은 입력과 출력을 텍스트로 받고 텍스트로 출력한다. 그러나 Jev는 일반적인 AI와 다르며 state와 questions을 입력받고,  typed answers, 확률, confidence를 출력한다. 하나씩 무엇을 의미하는지 알아보자.

### Input
Jev는 입력으로 State와 Question을 받는다. 아주 간단하게 설명하자면 State는 판단 대상이고, Question은 판단 대상에 던질 질문이다. 

#### State

[표1]과 같이 State는 문자열, Object(json), 배열로 작성될 수 있다. 공식문서에서는 대부분 Object로 작성하길 권한다. 더 분명하게 표현할 수 있기 때문이다.

| Format | Useful for | Example |
| :---: | --- | :---: |
| String | A message, article, or passage                      | `"My card was charged twice."`                                          |
| Object<br>(json) | Named fields, related records, or application state | `{"message": "My card was charged twice.", "order_id": "A-104"}`        |
| Array  | A sequence of messages or records                   | `["Hi", "My customer number is TS1337.", "My card was charged twice."]` |
*표 1. state의 다양한 형태*

#### Question
 Questions은 State에 대한 질문으로 정의할 수 있다. 입력부에서 Question이 정의될때 결과의 형태가 동시에 정의되어서 Question의 각 타입을 파악하고 적재적소에 사용하는 것이 필요하다. 표2와 같이 Choice, Score, Noul 형태로 작성될 수 있으며 의미는 다음과 같다 :
 
 - Choice : 말그대로 여러가지 선택지 중에 고르는 타입이다.
 - Score : 어느 정도 수준인지 숫자로 측정할 수 있는 타입이다.
 - Noul : 예, 아니오로 대답한다. 

| Type                         | What it answers         | Returns                                          |
| ---------------------------- | ----------------------- | ------------------------------------------------ |
| Choice | Which of these options? | `choice`, `probabilities`, `confidence`          |
| Score   | Which level?            | `score`, `legend`, `probabilities`, `confidence` |
| Noul     | Is this true?           | `noul` (0 to 1)                                  |
표 2. Question의 다양한 형태
 
 기본적으로 Question은 `ID`, `type`, `instructions`를 가지며 `criteria`는 선택사항이다. 각각의 의미와 예시는 다음과 같다.
 
 - `ID` : 각 request를 식별할 수 있는 이름이다.
 - `type` : Choice, Score, Noul중 하나이다.
 - `instructions` : state에 대해 질의할 수 있다.
 - `criteria` : 답변이 될 수 있는 후보를 작성할 수 있다. Choice에서는 선택지, Score는 기준, Noul은 네, 아니오에 대한 설명(예 또는 아니오가 되는 기준)을 작성할 수 있다.
 
 ```python
 from typesafe_sdk import Choice, TypeSafeClient
 
 with TypeSafeClient() as client:
    response = client.system_one(
        state="My running shoes arrived in the wrong size. Can I swap them for a size 10?",
        questions={
            "department": Choice(
                instructions="Which team should handle this?",
                criteria={
                    "returns": "Exchanges, wrong or damaged items",
                    "shipping": "Delivery status, delays, lost packages",
                    "billing": "Charges, invoices, payment problems",
                },
            ),
        },
    )

    print(response.answers["department"].choice)
 ```
*Code 1. request example*

#### Output
답변을 얻기전에 정의된 Question Type에 따라 응답의 형식 또한 정의된다고 언급했다. 상식적으로 Choice는 후보 선택지중 하나가 답변이 될것이고, Score는 점수로, Noul은 예 또는 아니오중 하나로 나올것이다. 따라서 `probabilities`, `confidence`만 설명하겠다.

- `probabilities` : choice의 경우 선택지가 선택될 수 있는 확률이다. Score의 경우 레벨이 선택 될 수 있는 확률이다. 
- `confidence` : `confidence`는 모델이 정답에 대해 얼마나 확신하는가를 나타내는 지표이다. 확률이 한쪽에 쏠려있으면 높게 나타난다.

| Type | Answer fields | How to read it |
| - | - | - |
| Choice | `choice`, `probabilities`, `confidence` | `choice` is the selected option. `probabilities` is the distribution across every option. `confidence` summarizes how peaked that distribution is. |
| Score | `score`, `legend`, `probabilities`, `confidence` | `score` is a position along your levels, and can fall between two of them. `legend` repeats the levels by number. `probabilities` is the distribution across levels. |
| Noul | `noul` | The probability that the answer is yes. Near 1 is a strong yes, near 0 a strong no, near 0.5 uncertain. Noul has no separate `confidence`. |
